# SVG renderer migration

Sketch Town keeps its hand-drawn art and uses the pinned GameKit vector-asset pipeline for character and fixed environment resources. This migration does not change simulation rules, movement, collision, save data, input sampling, or multiplayer state. The 17 fixed SVG assets are build-time resources; freehand strokes and effects that change during play remain runtime geometry.

## Source and build flow

- `source/assets/*.svg` is the authored source for the player, enemies, houses, trees, and individual environment props. Part pivots, sockets, expressions, and animation clips live in each file's `vector-asset` metadata.
- `scripts/compile-vector-assets.mjs` invokes the pinned GameKit Vector Assets 0.6.5 compiler with `curveSegments: 8` and writes the ignored `source/vector_assets.generated.js` registry. The browser never compiles SVG at runtime.
- `source/build_rpg.py` verifies the SDK manifests and checksums, embeds the exact official ESM module bytes, compiles the source bundle, and regenerates the root `index.html`.
- Rebuild with Node.js 22+, `npm ci`, and Python 3.10+: `python source/build_rpg.py`.

Vector Assets and its compiler remain pinned to `byh-playground/bloom-gamekit` v0.6.5, source commit `71b368bd85eaa1aa17fb841573da7fd9ffe0c9de`, distribution commit `b1bd32a1876fb8b096f483a93d1079da49e4fc74`. `source/gamekit/0.6.5/provenance.json` records the compiler and vector-asset checksums. The renderer module is independently pinned to GameKit v0.15.1, distribution commit `50f835a801a8fae3c982e051290a26555ac031df`; its manifest SHA-256 is `7540662fda050f8f2fcfdb6cc21818a136c0f8d3df93a53dcde68175f70c65b0` and `rendering.js` SHA-256 is `1a3790c3281de93ff361a8720eccfb03b60018b09937a84a8d4da02b3f73c9ba`. See `source/gamekit/0.15.1/provenance.json`. The four multiplayer ESM modules are separately pinned to GameKit v0.14.3 source commit `dd59a57fcf66409cef16632ffb433c0b760324fa` and dist commit `418e17c455db56d6ed073d82d115191d9dd8bf04`; their manifest is checked by the canonical build.

## Runtime boundary

`game_part3.js` maps current game state to an SVG clip and expression. Poses, enemy expressions, house variants, and plant sway are authored in SVG metadata. SVG meshes and runtime geometry share one GameKit WebGL device. The renderer flushes vector geometry before mesh boundaries so painter order, alpha blending, clipping, and depth ordering stay in the same order as the game calls; it does not globally reorder draws.

User-drawn strokes remain sampled runtime input and dynamic game geometry. They are not converted into SVG files or recompiled on each frame. Projectile trails, impacts, rings, and cast sparks also remain runtime geometry. Static player/enemy bodies and repeated environment objects are compiled once at build time and their GPU meshes are cached until disposal. A non-persisted `pagehide` releases every vector asset, the context, its device, and input resources. A persisted bfcache `pagehide` pauses the game loops while keeping those resources alive; persisted `pageshow` resumes them.

Each environment item has its own SVG mesh. This avoids submitting hidden geometry for every tree or house when shared environment art is used repeatedly. Repeated instances may be instanced when adjacent in painter order. The renderer preserves ordering boundaries and does not promise one draw per SVG asset or a fixed total draw count.

## Supported SVG

The compiler accepts the SVG elements `svg`, `metadata`, `defs`, `linearGradient`, `stop`, `g`, `path`, `rect`, `circle`, `ellipse`, `line`, `polyline`, and `polygon`. It supports solid fills/strokes and restricted linear gradients: direct root `defs`, explicit stops, `pad` spread, object-bounding-box or unitless user-space coordinates, and internal `fill="url(#id)"` references. Gradient stops are compiled to flat-colored triangles; there is no runtime gradient texture. See `source/gamekit/0.6.5/upstream-source/modules/vector-assets/compiler.js` for the complete contract.

The compiler rejects unsupported tags, attributes, namespaces, event handlers, external references, doctypes, and entities with an error; a build fails rather than silently dropping them. It does not support raster `<image>`, `foreignObject`, scripts, CSS stylesheets or `style`/`class`, radial gradients, gradient inheritance/transforms, `<use>`, filters, masks, or clipping paths. Clip paths remain unsupported. The 17 authored Sketch Town SVGs contain no gradients or `clipPath` elements and use none of these unsupported features.

## Runtime notes

- SVG meshes use the GameKit MeshRenderer and are uploaded once. GameKit 0.6.5 indexes bit-identical complete vertex records into a 16-bit index buffer while preserving triangle order; seeking a clip updates part transforms and does not rebuild geometry.
- The retained mesh renderer batches consecutive instances only when mesh, multipart poses, projection, clip planes, and depth state match. One-part static props can reuse a retained mesh across transforms. Independently animated multipart actors have different per-part poses and remain separate draws. `MeshBuilder.combine` is available for compatible groups up to 16 total parts, but it duplicates retained geometry and is not used as a per-frame workaround.
- The existing world and live drawing effects use GameKit's vector context on the same WebGL1 context. Vector paths and SVG mesh queues are flushed at their painter boundary to preserve source draw order.
- SVG `opacity`, fill opacity, and stroke opacity are compiled into per-vertex alpha. No raster textures are introduced by the migrated assets.
- The runtime device tracks context loss/restoration and owns the white vector texture and GPU buffers. The renderer skips a boundary frame if WebGL queries go unavailable just before the browser's loss event, then reuses retained meshes after restoration. Final page hide disposes the asset cache; bfcache suspend/resume keeps it intact. Resize continues through the existing renderer boundary.

## Fixed-scene draw census and combine experiment

The counts below come from actual WebGL device dispatches in a fixed scene on Edge 155 / ANGLE SwiftShader. The 1024×768 DPR1 desktop frame has 22 total dispatches: 6 `drawArrays` primitive/vector batches plus 16 indexed mesh dispatches. The 844×390 DPR2 mobile frame has 20 total dispatches: 6 `drawArrays` batches plus 14 indexed mesh dispatches. Thus the 20–22 totals are total GL dispatches, not mesh-only draws. Source SVG geometry uploads and geometry bytes uploaded were both zero in these sampled frames.

A temporary, non-production `MeshBuilder.combine` candidate was rendered for one contiguous static run. In the recorded event lists, dispatch metadata outside the selected run (kind, method, counts, instance/reference totals, and item order) matches; the selected source dispatches were replaced at the same painter position. Baseline and candidate readbacks were captured on adjacent renderer frames (desktop `stats.frame` 5→6; mobile 4→5). The saved JSON contains no matching simulation-tick snapshot or proof that rendering was frozen. The RGBA readbacks differ, but the evidence cannot attribute that difference solely to combining or establish controlled same-frame parity. No FPS comparison was run.

Occurrence-to-dispatch mapping in the saved records: desktop default occurrences 20–32 map to source `meshFlush` events 17–20 (2,700 + 300 + 7,200 + 717 references) and candidate event 17 (`combined:13`, 10,917 references). Mobile default occurrences 20–26 map to source events 17–19 (2,700 + 300 + 2,700 references) and candidate event 17 (`combined:7`, 5,700 references). The unselected dispatches retain their recorded order and metadata.

At desktop zoom 1.23 / rotation 0.17, no candidate draw was installed: the source dispatches covered 13,800 references while the selected geometry held 10,200, a 3,600-reference boundary mismatch involving neighboring visible canopy submissions already sharing source batches. No parity or FPS result exists for that view.

For the default desktop/mobile cases, the temporary mesh added 192,334 / 100,984 retained bytes while the original cached asset meshes remained resident. The candidate frame reported zero geometry uploads because the one-time setup upload happened before sampling. The combined mesh takes the multipart shader path, which applies a per-part transform that the original one-part meshes do not use. This is a possible contributor, but the adjacent-frame captures do not isolate it; no floating-point, SDK, or other root cause is established. The temporary candidate was not adopted.

A later controlled check used the same final bundle SHA (`3f4655495d2478c4c37ce07fb5594c31a42604e5e876cdd44c02ff0fa8bff1bf`) and the prior fixed scene frozen at tick 18 / 600 ms. On Edge 155 / ANGLE SwiftShader, two consecutive N renders had identical full-frame RGBA on desktop (3,145,728 bytes) and mobile-sized DPR2 (5,266,560 bytes), with unchanged state and draw sequence. The 22/20 dispatch reference sequences matched the saved source census. Forwarding the selected original draw calls through the no-op passthrough preserved every call, reference count, and pixel; each selected call was observed exactly once.

After those gates passed, an isolated static `environment-stump` comparison used the official pinned GameKit 0.15.1 renderer. The 249-vertex / 717-index one-part geometry was compared with an equivalent two-part encoding that assigns alternating triangles to two identity transforms at opacity 1 while preserving triangle order and all 717 references. Desktop and mobile-sized DPR2 renders each produced one indexed draw, zero GL errors, and exact full-frame RGBA (0 differing bytes; bounding box empty); the frozen pre-draw GL and game state matched. This isolates only the same-matrix, same-camera, opacity-1 part-shader path for this prop. It does not validate non-identity part offsets or opacity changes, the full heterogeneous combine candidate, or explain the earlier adjacent-frame pixel differences. The JS sources, reports, and PNGs are preserved under `%TEMP%\sketch-town-census-20261019\passthrough` outside the repository.

The benchmark separates two datasets. The earlier GameKit Vector Assets v0.6.5 fixed-scene sample (renderer bytes match v0.6.4) recorded a 16.4–18.9% desktop and 16.4–20.9% mobile-landscape SwiftShader FPS loss in two 4-second samples; these are not v0.15.1 measurements. A separate six-round paired comparison for the pinned GameKit v0.15.1 renderer is recorded below in the same benchmark: desktop median interval ties legacy WebGL1 L while p95 is 19.86% slower; the mobile-sized viewport is 16.60% slower at median and 14.21% at p95. The performance gate against L therefore remains open. CPU software-renderer results must not be presented as physical mobile performance. Lowering curve tessellation is still rejected because it visibly damaged rounded silhouettes for only a small software-renderer gain.

## Current verification status

Against the final GameKit 0.15.1 bundle (SHA-256 `3f4655495d2478c4c37ce07fb5594c31a42604e5e876cdd44c02ff0fa8bff1bf`), the existing offline `python source/e2e.py` run passed 64 checks with 1 public-network check not run (105.08 s), and `python source/e2e.py --flow online --live-p2p` passed 7/7 checks (44.18 s), including guest leave/rejoin and matching confirmed hashes. After extending the existing modal-button click wait from 1 s to 5 s without changing assertions, the existing `python source/e2e.py --flow progression --live-p2p` passed 55 checks (93.45 s), including actual online cast/skill execution, simultaneous PC/mobile gate opening, guest leave, same-room reconnect, restored gate/investments, equal confirmed RTC hashes, and no JavaScript errors. The timeout change addresses Playwright timing out before click dispatch under load; it does not change P2P readiness or product behavior. These runs used the existing E2E script and Edge 155 with WebGL1/ANGLE SwiftShader; mobile was viewport emulation, not a mobile device. The bundle and gameplay code were unchanged by the later documentation-only update.

PR #12 was explicitly approved for merge while the SwiftShader gate against legacy WebGL1 L remains open; that approval is not a performance pass. The existing pull-request build skips the deploy job, and a merge to main uses the repository's GitHub Actions Pages workflow. The pinned renderer exposes static `MeshBuilder.combine`, which concatenates compatible geometry in supplied painter order (up to 16 parts and 65,536 vertices); it does not provide arbitrary per-command global render state inside one combined draw, and nonempty index variants are unsupported on this path. The isolated identity multipart check does not establish full-scene heterogeneous parity or a performance win. Stage 4's combine experiment was not adopted; Stage 5's DPR result was inconclusive. See the benchmark for the unchanged N/L gap and preserved evidence.
