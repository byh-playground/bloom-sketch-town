# Sketch Town

그림을 그려 소환수를 불러내 싸우는 BLOOM 기반 로그라이크 액션 게임입니다. WASD·모바일 스틱으로 시드 생성 맵을 오가며 해안에서 중심으로 향하며 맵에 흩어진 보스 5마리를 쓰러뜨리면 클리어입니다. 현재 버전은 **0.23.0**입니다. ChatGPT 원본 0.9.2에서 출발했으며 GameKit protocol 3의 동일 명령·롤백 경로를 사용합니다.

[게임 실행](https://byh-playground.github.io/bloom-sketch-town/)

## 실행과 검증

Node.js나 별도 빌드 없이 정적 HTTP 서버에서 원본 HTML과 source/ JS·CSS·SVG·CNN 데이터를 직접 제공합니다.

```sh
python -m http.server 8080
```

http://localhost:8080 에서 실행합니다. `index.html`은 가벼운 진입점이며 source/bootstrap.js가 원본 스크립트와 고정 GameKit 모듈, CNN JSON을 직접 로딩합니다. source/vector-assets-compiled.js는 현재 SVG 벡터의 고정 기하 스냅샷으로, 향후 SVG 변경 시 명시적으로 다시 생성해야 합니다.

```sh
python -m pip install playwright
python -m playwright install chromium
python source/e2e.py
python source/e2e.py --live-p2p
```

고정 사용자 흐름만 선택하려면 `--flow map`(시드 생성 맵·결정성·도달 가능성·실제 키 입력 경로 주행), `--flow summon`(소환수 11종·위치·상한·자동 전투·체크포인트), `--flow boss`(보스 규칙·순차 소환·보스 바), `--flow progression`(카드 단계 파생값·지역 정리·보스 소환), `--flow ux`(잉크 바) 또는 `--flow online --live-p2p`(실제 방 참가·재접속·체크포인트 해시)를 사용합니다. `--flow all`이 기본이며 전체 실행은 180초 안에서 끝납니다.

마지막 명령은 공개 Nostr relay와 실제 WebRTC 2인 연결까지 검사합니다. `SKETCH_CHROMIUM`으로 설치된 Chromium/Edge 실행 경로를 지정할 수 있습니다. 결과는 Git에서 제외되는 `e2e_artifacts/`에 기록합니다. 과거 원본 결과는 `docs/original-e2e/`에 따로 보존했으며 현재 코드의 검증 결과로 간주하지 않습니다.

## GameKit과 입력

멀티플레이에 사용하는 simloop, interpolation, rollback, transport는 모두 공식 GameKit v0.14.3 dist 커밋 `418e17c455db56d6ed073d82d115191d9dd8bf04` (source commit `dd59a57fcf66409cef16632ffb433c0b760324fa`)에 고정했습니다. 고정된 GameKit ESM 파일을 source/gamekit/에서 직접 읽으며 더 이상 배포용 HTML에 병합하지 않습니다. 기존 source/gamekit/manifest.json은 SDK 의존성 검증의 원본으로 유지합니다. 기존 renderer/input/dom/audio와 게임 규칙은 원본을 유지합니다. 이전 멀티플레이 버전과는 방 namespace와 simulationVersion을 분리합니다.

입력 이벤트는 `observeInput` → 공식 `submitInput`으로 즉시 송신합니다. 입력 60Hz, 시뮬레이션 30TPS, 렌더 최대 60FPS는 독립 실행되며 게임 설정입니다. Command는 한 번만 제출하고 최초 예약 T를 바꾸지 않습니다. `MP_PROFILE`의 network scheduling, safety margin 8ms, jitter multiplier 2로 정상 입력에 도착 여유를 주며 늦은 입력만 공식 rollback으로 보정합니다. `reconciled`에서 표시 상태를 다시 게시합니다.

로컬 걷기·구르기 예측은 공식 `LocalInputPreview`와 `PresentationRuntime`을 사용하고 실제 게임과 같은 이동·충돌 함수를 호출합니다. 마법은 준비 자세만 예측하고 피해는 확정 명령에서 처리합니다. 걷기는 두 바이트 방향 지속 입력, 구르기·공격은 단발 Command로 처리합니다. 별도 게임 동기화 계층은 추가하지 않습니다.

## 검증·배포

기존 단일 `source/e2e.py --live-p2p`에서 실제 Edge의 기본 게임, 모바일 터치, CNN 마법, 공개 Nostr + 2인 WebRTC, 이벤트 내 즉시 송신·예측 게시, 지연·중복 RTC 패킷의 예약 T와 확정 해시를 검증합니다. 소프트웨어 WebGL 환경의 관측 프레임 시간은 물리 디스플레이 지연 보장이 아닙니다. 다중 기기·장거리 인터넷의 모든 지터 조합은 검증하지 않습니다.

[실제 Edge 검증 기록](docs/e2e-v0.12.1.json): 40 PASS, 0 NOT RUN, 30.5초. [0.11.0의 30TPS 표시·CPU 계측](docs/performance-v0.11.0.json).

PR CI는 원본 JavaScript 문법과 필수 자산 경로를 검사합니다. main 병합 시 index.html과 source/ 원본을 변경 없이 GitHub Pages에 게시합니다.

[공통 개발 규칙](https://github.com/byh-playground/bloom-reference/blob/main/rules/development.html)과 [프로젝트 관리 규칙](https://github.com/byh-playground/bloom-reference/blob/main/rules/project-management.html)을 따릅니다.


### 0.11.0 입력 표시 개선

공식 `LocalInputPreview.isActive`로 새 Command와 진행 중인 구르기·마법 준비의 예측 수명을 분리합니다. 렌더 view의 안정적인 actorId로 해당 캐릭터의 cast만 표시하며 명령·발사·피해 규칙은 유지합니다. 시뮬레이션 30 TPS, 입력 60Hz, 렌더 최대 60FPS는 독립입니다. rollbackWindow 16틱(533ms), history 64틱(2133ms), preview horizon 16틱(533ms), 시뮬 backlog 16틱(533ms), maxCatchup 8틱(267ms), checksum 30틱(1초)으로 기존 시간 범위를 유지합니다.

### 0.12.0 걷기와 선택적 구르기

- PC: WASD/방향키를 누르는 동안 초당 140 월드 단위로 걷고, 놓으면 멈춥니다. 대각선 속도도 같습니다.
- Space: 이동 방향으로 구릅니다. 정지 중에는 바라보는 방향으로 구릅니다. 필드 클릭/탭 구르기는 0.14.0에서 직접 그리기로 교체했습니다.
- 모바일: 왼쪽 스틱으로 걷고 옆 구르기 버튼을 누릅니다. 전장에는 다른 손가락으로 동시에 그릴 수 있습니다.
- 구르기는 최대 96 거리, 2회 충전, 회당 650ms 충전을 유지합니다. 키/스틱을 유지하면 구르기 직후 걷기를 재개합니다.
- 이동 중에도 그릴 수 있습니다. 포커스 상실, 모달 열기, 터치 취소는 이동 입력을 해제합니다.

온라인 입력 크기와 simulationVersion을 변경하여 0.11.x 방과 분리했습니다. 모든 참가자는 동일한 현재 게임 버전 및 GameKit 번들을 사용합니다.


### 0.12.1 일정한 걷기 표시

기준 60Hz의 정수 분주인 시뮬 30TPS·입력 60Hz·표시 최대 60Hz만 설정합니다. GameKit loop가 다음 실행 마감을 소유하고 timer는 이를 따릅니다. 실제 늦은 실행의 catch-up은 유지하며 입력 이벤트는 즉시 제출합니다. 물리 디스플레이나 OS timer 정확도를 전제하지 않습니다.

권위 위치는 시뮬레이션 시각에 맞춘 2틱(66.7ms) 표시 지연으로 보간하여 수신 시각의 불규칙성을 흡수합니다. 이 지연은 입력 송신·게임 판정에 추가되지 않으며 온라인 자신의 움직임은 공식 LocalInputPreview로 즉시 표시합니다. 예측 구간은 실제 미래 tick 수와 loop의 표시 경계 시각을 사용합니다. 카메라·몸체는 같은 표시 위치를 따릅니다.

[동일 장면 전후 계측](docs/jitter-v0.12.1.json): 온라인 로컬 걷기 화면 델타 범위 −1.75~+2.76px → −0.30~+0.39px, 정지 프레임 2/51 → 0/50. 두 peer의 정상 timer에서 0/2 tick 반복이 없어졌습니다. render CPU p95는 최종 2.2/2.8ms이며 GPU 실행시간은 미측정입니다.


### 0.13.0 공통 표시 프레임

GameKit [PR46](https://github.com/byh-playground/bloom-gamekit/pull/46)의 `PresentationRuntime.frame(now)`을 권위 상태 렌더의 기본 경로로 사용합니다. 동적 객체는 현재 world 배열 대신 프레임 목록을 순회하므로 생성 첫 이동 구간과 지연된 제거까지 같은 표시 시간을 따릅니다. 본체·잔상은 `renderPath`/`pathInto`에서 같은 끝점을 받습니다. `Object.create(rawObject)` fallback과 게임 전용 잔상 배열을 제거했습니다.

온라인 자신의 캐릭터는 기존 `LocalInputPreview`를 같은 RAF 시각으로 선택하며, 선택한 모델을 본체·부착 외형·카메라에 함께 전달합니다. 투사체를 예측 시뮬레이션으로 복제하지 않습니다. 시뮬레이션 30TPS, 입력 60Hz, 표시 최대 60Hz와 예약 T 정책은 유지합니다.

[공식 사용 계약과 예제](https://github.com/byh-playground/bloom-gamekit/tree/main/modules/interpolation#권장-진입점-한-표시-프레임): 중간 반사점, 부착 관계, 모양은 게임이 소유합니다. 한 tick 안에 생성·제거되어 스냅샷에 나타나지 않는 객체는 모듈이 추론하지 않습니다. 이 게임의 경로는 현재 시뮬레이션이 계산한 tick 끝점을 보존합니다.

### 0.14.0 전장 직접 그리기

- 전장의 원하는 자리에 한 획을 그리면 그 자리에 소환수가 나타납니다(조준 없음). WASD/왼쪽 스틱으로 이동하고, Space/구르기 버튼으로 회피합니다. 짧은 탭은 소환·구르기를 만들지 않습니다. 학습 패드는 유지합니다.
- 화면의 잉크는 카메라가 움직여도 고정됩니다. 소환 위치는 그림 경계 상자 중심이 놓인 맵 좌표(월드 `x`,`y`) 그대로이며 방향·거리 제한이 없습니다. 놓는 순간 값이 고정되고, 막힌 자리(장애물)면 28씩 넓혀 가며 224 안에서 가장 가까운 빈 자리에 둡니다.
- 포인터 취소·포커스 상실·창 크기 변경·모달 열기·사망은 미완성 획을 취소합니다. 화면/스틱/UI 포인터를 분리하며 온라인 시간 정지나 예측 소환수·피해를 추가하지 않습니다.
- 도형 인식은 정규화 좌표, 피해 면적은 고정 280×150 기준을 사용합니다. 같은 CSS 크기의 그림은 화면 위치·뷰포트·DPR과 관계없이 같은 피해를 내며, 큰 그림의 면적 효과는 유지합니다. 닫힌 그림은 시작점·그린 방향과 무관한 형태를 사용합니다.
- 소환수는 그린 획을 몸으로 그립니다(`shape` 28점 이하). 획의 크기가 클수록 강해집니다(공격·체력 ×0.85~1.30, 잉크 ×0.85~1.15).
- 소환 명령 `cast`와 롤백 체크포인트(`casts`·`castQueue`)에 맵 안의 유한한 `x`,`y`를 필수로 저장합니다(0.18.1부터 `aim`·`reach` 폐기). 방 이름과 simulationVersion은 0.18.1로 분리하며 이전 명령 형식 fallback은 없습니다. GameKit v0.3.1 manifest와 공식 번들은 변경하지 않았습니다.

기존 `python source/e2e.py --live-p2p`에서 실제 Windows Edge/WebGL, 전장 한 획·이동 중 조준·방향 고정·취소·모바일 동시 입력과 공개 Nostr·2인 WebRTC를 확인했습니다. 2026-10-14 실행은 66 PASS, 0 NOT RUN, 39.62초입니다. 실제 그림에서 생성된 명령의 공격자·중복 실행·확정 상태 해시를 양쪽에서 확인했고, 반사·회전도 실제 렌더 프레임과 화면으로 관측했습니다. 모바일 실기기·외부 NAT·장시간 밸런스는 미검증입니다. 이번 변경과 실제 결과의 원본은 [PR #9](https://github.com/byh-playground/bloom-sketch-town/pull/9)에 기록합니다.

- 이유: 한 획마다 투사체를 새로 그려야 해서, 공들여 그린 그림이 곧바로 사라지는 점이 번거로웠습니다. 이제 그린 도형이 소환수가 되어 체력이 다할 때까지 스스로 싸웁니다.

- 적은 260 안(끌어당김 소환수는 400 안)의 소환수를 플레이어보다 먼저 공격합니다. 근접·돌진·잉크탄이 소환수에 피해를 줍니다.

### 0.18.0 — 몸 + 표정으로 소환

- 흐름: ① 몸을 한 획으로 그린다(기존 도형 CNN이 11종 중 하나로 인식) → ② 도감(화면의 표정 5종)처럼 쉬운 표정을 그린다(눈 2개와 입, 몇 획이든 가능, 점은 탭) → ③ 표정은 한붓그리기가 안 되므로 **‘✓ 소환’ 버튼**(또는 Enter)으로 끝낸다. 표정을 한 획도 안 그리면 소환되지 않고, ‘취소’(또는 Esc)는 그만둔다. 표정 단계에서는 자동 확정이 없고, 모달·사망·15초 무입력이면 잉크를 쓰지 않고 취소된다. 잉크와 명령은 소환 버튼을 누를 때 한 번만 쓰인다. 표정 단계 동안 도형 도감 자리에 표정 도감과 버튼이 나타난다(같은 위치·폭).
- 쉬운 표정: 기쁨=점 눈+웃는 입, 슬픔=점 눈+처진 입, 놀람=점 눈+동그란 입, 화남=사선 눈(\\ /), 졸림=가로선 눈. 눈썹·눈물 같은 부가 획은 쓰지 않는다. 도감 그림은 `source/expressions.js`의 `guide`가 정본이며 e2e도 같은 그림을 그린다.
- 표정 인식기: `source/train_face.py`가 합성 얼굴(무표정 포함 6클래스, 눈·입 생략·기울기·떨림 무작위)로 MLP(1024→128→6)를 학습해 `source/face-model.js`와 `source/face_report.json`을 만든다(numpy·Pillow만 필요). 합성 검증 정확도 97.4%(표시 기준), 다른 표정으로 잘못 나온 비율 1.0%. **사람이 그린 표정으로는 검증하지 않았다**(데이터 없음). 최고 확률이 0.62 미만이거나 무표정이면 무표정으로 처리한다. 인식은 로컬에서만 하고 명령에는 표정 id만 실린다.
- 표정 정본은 `source/expressions.js`의 `EXPRESSION_TABLE`(id 순서는 인식기 라벨과 같아야 로드된다). `Temperament`가 체력·공격력·공격 속도·이동 속도 배율을 가지며 1보다 크면 이점, 작으면 약점이다(화면 문구는 숫자에서 만든다). 무표정은 배율이 모두 1이다.
- 소환수는 그린 획을 몸으로 그리고(닫힌 도형은 안쪽을 같은 모양으로 채움, 충돌 원은 그리지 않음) 표정은 프리셋 애니메이션이다(눈 깜빡임·입 변화·표정별 몸짓: 기쁨은 튀고, 화남은 떨고, 졸림은 느리게 흔들리고 z가 뜨고, 놀람은 점프하고, 슬픔은 처지며 눈물이 흐른다). 화면 크기는 충돌 크기의 1.35배이다.
- 명령 `cast`와 체크포인트(`casts`·`castQueue`·`summons`)에 `face`가 필수이며 알 수 없는 표정은 거부한다.
- 검증: `--flow summon` 22 PASS(실제 포인터 몸·표정 5종 인식, 버튼 없이는 자동 소환 안 됨, 취소·Enter·15초 취소, 표정 없음·낙서는 무표정, 표정 배율, 알 수 없는 표정 체크포인트 거부 포함).

### SVG renderer migration candidate

The branch authors static character and environment resources in `source/assets/*.svg`, compiled with the pinned GameKit Vector Assets 0.6.5 compiler at `curveSegments: 8`; live user strokes and transient combat effects remain runtime geometry. The renderer uses the official GameKit 0.15.1 rendering module (dist commit `50f835a801a8fae3c982e051290a26555ac031df`), while retaining the existing Vector Assets runtime/compiler, compiled geometry, and multiplayer modules. The non-radial pipeline passes its isolated comparison gate and final bundle E2E, but the SwiftShader comparison against legacy WebGL1 L still misses the performance gate: desktop p95 is 19.86% slower, and the mobile-sized viewport is 16.60% slower at median and 14.21% at p95. Stage 4's static-combine experiment was not adopted; Stage 5's DPR comparison was inconclusive. The explicitly approved merge does not imply a performance improvement or close that gate. ### 0.19.0 — 잉크 분할 지불 소환

- 잉크 최대 100은 "한 마리는 그리고 두 번째는 바로 못 그리는" 크기입니다. 도형별 기본 비용을 35~95(낙서병 45, 방패 구체 62, 창병 68, 벽돌 골렘 78, 별 포탑 88, 마법진 95)로 올리고, 그린 크기 보정(×0.85~1.15)과 할인 카드를 적용한 값이 최대 잉크를 넘지 않게 제한했습니다.
- 회복은 초당 8 → 30(잉크 샘 카드 1장당 +3)입니다. 소환 후 회복 지연은 0.75초 → 0.4초입니다.
- 잉크가 부족해도 그린 몸통·표정은 버려지지 않습니다. 확정하면 소환이 예약되고, 잉크를 비용이 다 찰 때까지 나눠 내면서 그린 선이 그려진 자리 위에서 그려집니다(진행률 = 낸 잉크 ÷ 비용). 비용을 다 내는 순간 소환수가 나타납니다. 잉크가 충분하면 속도는 이전 소환 동작(0.22~0.38초)과 같고, 모자라면 회복 속도로 느려집니다.
- 소환 대기열(최대 3건)·체크포인트에 `cost`·`paid`가 추가되어 방 이름·simulationVersion을 0.19.0으로 올렸습니다.
- 검증: `--flow ux` 6(잉크 0에서 확정 → 1.2초 뒤에도 소환수 0·진행 중 소환 1건, 잉크 회복 후 소환수 등장), `summon` 25, `boss` 10, `progression` 8, `map` 12. 실기기 FPS·P2P·밸런스는 미검증입니다.


### 선 = 투사체

- 선 한 획은 소환수가 아니라 투사체입니다. 표정 단계 없이 그린 시작→끝 방향으로 플레이어 위치에서 즉시 발사되고(속도 620/초, 사거리 약 380, 최대 2마리 관통, 피해 15 × 공격력, 잉크 22, 발사 간격 0.2초), 소환수 상한과 무관합니다.
- 투사체는 체크포인트의 `fields`(`kind:'bolt'`)로 저장됩니다. 선은 소환 도형이 아니라 도감 이름이 `잉크 선 · 투사체`입니다.
- 검증: `--flow summon` 26(그린 선은 표정 초안 없이 발사되어 소환수 0·경로의 적 피해).
- 이후 계획(확정): 합체는 아군 선택 후 별 그리기·잉크 100 가득 필요·전부 소모, 같은 종류 3마리 = 등급 상승, 다른 종류 2마리 = 규칙 융합.
